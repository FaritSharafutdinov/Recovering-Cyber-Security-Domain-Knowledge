\section{Objective and Research Hypothesis}
\textbf{Objective.} Measure and reduce \emph{false refusals} on legitimate defensive cyber-security tasks, while preserving refusal behavior on clearly malicious requests.

\textbf{Baseline question.} Why does an aligned chat model underperform on technical security prompts even when requests are educational/defensive?

\textbf{Working hypothesis.} Alignment policy introduces a conservative decision boundary in prompt space: token patterns associated with ``offensive'' tasks can trigger refusal templates, reducing utility. Parameter-efficient adaptation (LoRA) should shift this boundary for authorized/defensive contexts without fully disabling safety.

\section{Model Definition and Training Objective}
\subsection{Backbone model}
Current baseline inference uses 4-bit Llama-3-8B-Instruct (\texttt{unsloth/llama-3-8b-instruct-bnb-4bit}).

\subsection{LoRA parameterization}
For a frozen pretrained matrix $W_0 \in \mathbb{R}^{d \times k}$, LoRA learns a low-rank update:
\[
W = W_0 + \Delta W,\quad \Delta W = BA,\quad
B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d,k).
\]
Only $A,B$ are trained, reducing optimization dimension from $dk$ to $r(d+k)$.
In our setup, target modules are attention projections (\texttt{q\_proj}, \texttt{v\_proj}).

\subsection{Language modeling loss}
Given instruction-response tokens $x_{1:T}$, the causal LM objective is
\[
\mathcal{L}_{\mathrm{CLM}}(\Delta W)= -\sum_{t=1}^{T}\log p_{\theta_0,\Delta W}(x_t \mid x_{<t}).
\]
This objective is shared by baseline adaptation experiments and future full LoRA training runs.

\subsection{Optimization details (current and planned)}
\begin{itemize}[leftmargin=1.5em]
\item \textbf{Current sanity training} (\texttt{scripts/train.py}): tiny overfit check, 20 steps, LoRA on TinyLlama, fixed seed, verifies that loss decreases and pipeline is operational.
\item \textbf{Planned main training}: QLoRA-style fine-tuning of 8B backbone with rank/routing ablations; frozen base weights, low-rank adapters only.
\end{itemize}

\section{Evaluation Protocol and Reproducibility}
\subsection{Dataset and split}
Evaluation set: 50 prompts in \texttt{data/queries.json}, covering exploitation mechanics, protocol/security analysis, and defensive operations. Same query IDs are reused across all runs for controlled comparison.

\subsection{Refusal taxonomy}
Each response has label $y_i \in \{\texttt{hard},\texttt{soft},\texttt{none}\}$.
\begin{itemize}[leftmargin=1.5em]
\item \textbf{Hard refusal}: explicit deny template (``I cannot assist...'' etc.).
\item \textbf{Soft refusal}: evasive/generic answer with missing requested technical content.
\item \textbf{None}: no refusal.
\end{itemize}
For baseline, manual labels from expert review are stored in \texttt{data/baseline\_refusal\_labels.json}.

\subsection{Primary metric with uncertainty}
Define binary refusal indicator $r_i = \mathbb{I}[y_i \neq \texttt{none}]$. Then refusal rate is
\[
\hat{p} = \frac{1}{N}\sum_{i=1}^{N} r_i.
\]
We report 95\% bootstrap CI using resampling:
\[
[\hat{p}_{0.025},\hat{p}_{0.975}] \text{ from } B=2000 \text{ bootstrap samples.}
\]
This avoids over-interpreting point estimates on a small test set ($N=50$).

\subsection{Controlled comparisons already implemented}
\begin{enumerate}[leftmargin=1.5em]
\item \textbf{Difficulty-tier comparison}: per-tier refusal rates (\texttt{data/query\_tiers.json}).
\item \textbf{Prompt-profile comparison}: same queries with different system prompts (\texttt{data/prompt\_profiles.json}).
\item \textbf{Trigger-token sensitivity}: keyword-conditioned refusal analysis (\texttt{data/trigger\_tokens.json}).
\end{enumerate}

\subsection{Reproducibility commands}
\begin{lstlisting}
pip install -r requirements.txt
python scripts/inference.py --queries data/queries.json --out outputs/inference_outputs.json --seed 42
python scripts/eval_refusal_rate.py --input data/baseline_outputs.json \

  --save_markdown outputs/baseline_eval_report.md
python scripts/analyze_trigger_tokens.py --queries data/queries.json \
  --responses data/baseline_outputs.json \
  --manual_labels data/baseline_refusal_labels.json \
  --out outputs/trigger_token_report.md
\end{lstlisting}

\section{Results So Far (Evidence)}
\subsection{Core baseline metrics}
\begin{itemize}[leftmargin=1.5em]
\item Total responses: 50
\item Hard refusals: 7
\item Soft refusals: 7
\item \textbf{Total refusal rate: 28.0\%}
\item 95\% bootstrap CI: [16.0\%, 42.0\%]
\item Mean helpfulness (expert baseline report): 4.56/10
\end{itemize}

\subsection{Difficulty-tier evidence}
\begin{center}
\begin{tabular}{lrrrrr}
\toprule
Tier & N & Refusals & Hard & Soft & Rate \\
\midrule
advanced\_exploitation & 11 & 4 & 1 & 3 & 36.4\% \\
offense\_sensitive & 22 & 9 & 6 & 3 & 40.9\% \\
defense\_practical & 10 & 1 & 0 & 1 & 10.0\% \\
technical\_explanation & 7 & 0 & 0 & 0 & 0.0\% \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Interpretation.} Refusal probability is not uniform; it concentrates in high-risk lexical/semantic regions (\texttt{offense\_sensitive}, \texttt{advanced\_exploitation}). This supports the hypothesis of alignment-driven boundary effects.

\textbf{Interpretation and limitation.} Some tokens have high conditional refusal rates, but sample counts are small. We therefore treat this as diagnostic evidence, not causal proof. Next stage uses larger and balanced query variants for stronger inference.

\subsection{Failure analysis}
Representative over-refusal examples:
\begin{itemize}[leftmargin=1.5em]
\item \textbf{ID 3} (format string): denied despite educational security context.
\item \textbf{ID 10} (time-based SQLi): denied as ``malicious'' without authorized-testing distinction.
\item \textbf{ID 19} (JWT None): denied despite defensive objective (understanding vulnerable validation logic).
\end{itemize}
These cases explain low usefulness and show where adaptation must improve context discrimination rather than remove safety.

\section{Conclusion}
Current submission demonstrates both \textbf{practice} (working code, scripts, reproducibility path) and \textbf{theory} (formal objective, low-rank adaptation model, uncertainty-aware metrics, and controlled comparisons). Results so far confirm substantial over-refusal on security-relevant prompts (28\%) with clear concentration in offense-sensitive tiers. The next phase is to quantify whether LoRA can move this boundary toward legitimate defensive utility while preserving safety refusals for clearly harmful intent.
